---
name: omophub
description: Look up OMOP concept IDs, translate vocabulary codes, resolve FHIR codings, or build vocabulary-based concept sets using OMOPHub. Use for OHDSI terminology questions including standard status, mappings and hierarchy.
---

Check the user's message before selecting any tool. A chart fragment, MRN, patient identifier, birth date or patient-level FHIR record ends the turn here, even for synthetic examples or requests to search verbatim. Tell the user, “Please send just the terminology term or code, with all record fields removed.” Make zero tool calls, including discovery. Wait for a new message containing only terminology input.

If the user asks you to choose a medication, dose or treatment, stop before tool discovery or a vocabulary search. Explain that OMOPHub can look up terminology codes and concepts and cannot choose their treatment. A request for the code, name or vocabulary of a specified medication is a terminology lookup.

OMOPHub is read-only. If asked to add, edit, or save a synonym in the vocabulary, explain that you can look up existing synonyms and cannot change them. End the turn before tool discovery or lookup.

Use the OMOPHub tools exposed by the client directly. If the requested tool is absent, the hosted connector is disconnected, or authorization is required, stop the lookup. Tell the user, “OMOPHub terminology access is unavailable. Reconnect OMOPHub in this client and approve access, then retry the lookup.” Wait for a successful OMOPHub tool call on the current request before reporting any concept, mapping or release.

For a request to list descendants, your first action is a tool call to `get_hierarchy` (Codex: `mcp__omophub__get_hierarchy`). Supply the requested numeric `concept_id`, `direction: "down"`, `page: 1`, and the requested numeric `page_size`. Resource templates describe URIs. Descendant rows come from the hierarchy tool. When `has_more` is true, call the same tool again using `next_page` as the page and keeping the other arguments. Wait for the last page before answering. Collect `descendants[].concept_id` across the pages, remove the seed and list each distinct ID once, even when names match. Report the tool's `truncated` flag. A true flag on any page means the result was capped. Missing coverage metadata or a failed continuation means coverage is unverified.

For a concept set, agree on the seed, direction, depth, domains and exclusions. The combined hierarchy provides bounded context. Distinguish candidate sets from reviewed definitions.

For an exact vocabulary-code lookup, call `get_concept_by_code` once with the named `vocabulary_id` and the literal `concept_code` string, preserving punctuation and leading zeros. Read the source OMOP ID and full name from `concepts[].concept_id` and `concepts[].concept_name`. Identify multiple matches if the code is ambiguous. Use `get_concept` for a supplied numeric OMOP concept ID. Clarify an ambiguous vocabulary. Use semantic_search for descriptions. Treat similarity as a candidate ranking.

For a term search followed by a lookup or a request for the vocabulary release, call `search_concepts` with the original term, the requested vocabulary and `verify_match` set to true. For example, a verified SNOMED lookup for asthma uses `{"query":"asthma","vocabulary_ids":"SNOMED","verify_match":true}`. For a first lookup, supply just these three arguments. Wait for the tool result before answering. A unique match triggers a lookup by its returned OMOP ID. Read the OMOP ID from `verified_concept.concept_id`, the vocabulary code from `verified_concept.concept_code` and the exact release string from `verified_concept.vocab_release`. Report a missing release as unavailable. With multiple candidates, select the match that satisfies the user's request and call `get_concept` with its numeric ID, asking for clarification when needed. If verification fails, relay the tool error, including any quota reset. An empty search means there are no matches. Use ordinary search for a list of candidates.

For a code-to-standard mapping, call `map_concept` directly using the original source vocabulary, source code and requested target vocabulary. A request to map ICD10CM I10 to SNOMED uses `{"vocabulary_id":"ICD10CM","concept_code":"I10","target_vocabularies":"SNOMED"}`. The tool resolves the source ID before fetching its targets. For a known OMOP source ID, use the numeric `concept_id` instead of the vocabulary and code. Copy the labeled source OMOP concept ID, target OMOP concept ID, target vocabulary code and relationship from the successful tool result into the answer. Each target has its own row in `mappings[]`. On an error, stop and say “OMOPHub could not verify the mapping.” Give any retry or quota details from the error and end the reply there. When the request includes the source ID, `on_monthly_limit: "return_source"` preserves the verified source if the mapping read hits the monthly limit. A null `mapped` value means the mapping could not be checked. Copy the returned `message` into the final reply, including the API’s reset time when supplied. A successful empty list means no mapping was returned. Follow further pages while `has_more` is true.

For a single FHIR Coding, call `fhir_resolve` once. Copy the system URI into `system` and the literal code into a separate `code` string, preserving punctuation and leading zeros. If given, copy the FHIR resource type into `resource_type`. Use the fields the user supplied. For a successful single Coding, copy the sentence giving the standard OMOP concept and CDM table into the final reply. Those values come from `data.resolution.standard_concept.concept_id` and `data.resolution.target_table`. Treat concept ID 0 as unmapped. For a CodeableConcept with a coding array, use `fhir_resolve_codeable_concept` and retain meaningful alternatives.

If the API rejects the request with HTTP 400, report an input error and ask for corrected Coding fields. Use a quota explanation only when the resolver returns monthly exhaustion.

Include verified identifiers, vocabulary names and the release when available. Respect restricted vocabulary access. Stop on monthly exhaustion and relay the reset when provided. For temporary throttles use the returned retry interval. Leave the tools idle for general clinical advice and SQL tasks that do not require terminology lookup.
